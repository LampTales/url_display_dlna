# Android 平台兼容性

## 已知范围

应用的 `minSdk` 为 26，因此目标范围是 Android 8.0 及以上。核心投屏链路使用 Android 标准网络 API、UDP SSDP、多播锁、HTTP 服务和系统文件选择器，没有依赖 OPPO 私有 API。

因此，满足以下条件的 Android 设备原则上可以运行：

- 能连接到与播放设备相同的局域网；
- Wi-Fi 网络没有屏蔽 SSDP 多播或客户端之间的访问；
- 系统允许应用在需要时运行前台服务，并能访问手机的局域网 IPv4 地址；
- 播放设备支持应用发送的标准 DLNA `MediaRenderer:1` / `AVTransport:1` 操作。

## 尚未验证的部分

当前实机测试主要使用一台 OPPO 手机和 ColorOS。不能据此保证所有厂商都表现一致，尤其是：

- MIUI/HyperOS、OriginOS、鸿蒙兼容 Android 环境及其他系统可能有不同的多播、后台和省电策略；
- Android 13 及以上的通知权限会影响中转服务通知显示；
- Android 14/15 及厂商系统可能进一步限制前台服务、锁屏后的网络连接或电池优化豁免；
- 不同文件选择器对云盘、媒体库和 `content://` 文件的随机读取能力不同；
- 热点、访客 Wi-Fi、企业 Wi-Fi、VPN 和多网卡环境可能阻断 SSDP 或播放设备访问手机。

这类差异通常不是 Java 代码本身不兼容，而是系统网络或后台策略不同。遇到搜索不到设备时，先确认手机和接收端在同一网段，并关闭会隔离客户端的 VPN/访客网络；遇到中转播放中断时，检查该系统的后台运行和电池优化设置。

## 建议的扩展测试矩阵

公开发布后，至少在一台 AOSP/Pixel、OPPO/ColorOS、小米/HyperOS 和 vivo/OriginOS 设备上验证：设备搜索、直链投送、手机中转、本地视频、锁屏/后台、Seek、停止和播放结束。测试结果应记录 Android 版本、厂商系统版本、网络类型和接收端型号。
